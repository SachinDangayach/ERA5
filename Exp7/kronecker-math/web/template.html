Embeddings that already know what nine is

A 35-number block, appended to the Kronecker word embedding, in which adding two integers is adding two vectors' phases and multiplying them is the same operation on a second channel. Nothing is learned; the arithmetic is a property of the encoding. Every figure below is computed live in your browser by a port of the same codec the experiments use.

The goal

What "storing mathematics in an embedding" has to mean

The assignment asks that E(9) contain the meaning of nine, so that combining E(9) with E(9) gives you E(18). Written out, we need a fixed vector operation whose result is the embedding of the answer — a homomorphism, so that the structure of the integers survives being turned into vectors:

   (a, b)  ────  a + b  ────►   a + b
      │                            │
   encode                       encode
      ▼                            ▼
 (E(a), E(b)) ───   ⊕   ────►  E(a) ⊕ E(b)   ==   E(a + b)

Getting the right number back is weaker than this. The square has to commute: the two paths must land on the same vector. E1 checks exactly that, slot by slot, for whatever numbers you type.

One operation cannot do both jobs. If a single ⊙ gave E(a+b) and E(a·b), the same output vector would have to decode to both. So + and × get separate maps — which is what you would expect, since they are different operators. What is shared is the representation: one block of numbers serves both, and each operation is the same primitive applied to a different part of it.
The mechanism

Follow one pair of numbers all the way through

Everything below is computed live from the numbers in these two boxes. Change them and every table on this page updates.

1Addition is rotation

Put a number on a circle. Store a mod p as an angle, α = 2π·(a mod p)/p, kept as a (cos, sin) pair. Adding angles adds residues, and adding an angle is just complex multiplication of that pair — so + on integers becomes an elementwise complex product on vectors. Free.

2The Chinese Remainder Theorem puts the integer back

a mod p for one prime throws almost everything away. Do it for several coprime primes and the integer is pinned down uniquely up to their product. Each row below is an independent rotation — no carries, no sequential steps.

3Multiplication is also addition, in disguise

This is the part that makes the whole thing work. Modulo a prime, the nonzero numbers form a cyclic group under multiplication: pick a generator g and every value is gd. That exponent is the discrete logarithm, and dlog(a·b) = dlog(a) + dlog(b). So multiplication becomes addition of exponents — and addition is rotation again. Store a second angle, μ = 2π·dlog(a)/(p−1), and use the same primitive on it.

4Zero, the awkward case

dlog(0) does not exist, so one slot per prime flags a ≡ 0 (mod p). Under multiplication it updates as z ← za + zb − zazb, which is still bilinear and still needs no lookup. It also doubles as the block's own certificate of whether division is legal.

The object itself

What one number's block actually looks like

Five real numbers per prime. Seven primes gives 35 numbers, exact over 0 … 37,182,144. On an 8096-wide model width that is 0.43% of the embedding, appended after the Kronecker byte window — the existing 32 word slots are left completely untouched.

The design question

Why phases, and not just store the number?

A fair objection: store a as one scalar and addition is plain vector addition. Four encodings of the same number are compared below under the same noise, because this is the argument that decides the design.

0.050 encoding —

Two properties carry the argument, and only the second one is decisive. Errors snap to zero: decoding rounds each dial to its nearest legal lattice point, so a small error becomes no error, while a raw scalar that is off by 0.3% stays off by 0.3% and decodes to the wrong integer. But a one-hot digit encoding snaps just as well, so that alone would not justify the design. Arithmetic stays elementwise: adding digits needs carries — a sequential, non-local computation, and learning a carry rule that still holds at unseen magnitudes is exactly where the digit baseline fails in E3. Residues add componentwise, in one step, at any magnitude, and that is what no positional encoding gives you.

Reading it back

Decoding, three levels

A network never emits the numbers you asked for, so the decoder is not an afterthought. Each level below costs nothing extra in storage.

The middle row is free accuracy: every residue is already stored twice — once as an additive angle, once as a multiplicative one — plus the zero flag, so picking the nearest of the p legal five-slot patterns uses roughly twice the evidence of reading a single angle, at identical storage.
The one piece of glue

The refresh, and how to make it linear

After ⊕ fixes the additive channel, the multiplicative channel is stale — it still describes the old number. A refresh rebuilds it: a fixed lookup of p entries per prime, parameter-free, but not linear. A reviewer is entitled to ask whether the whole construction can be done with nothing but complex products and fixed matrices.

Why a model cares

What this buys a transformer

An ordinary learned embedding picks up magnitude from data, so magnitude only exists where data existed. Here the structure is in the encoding, so it is present at magnitudes that were never trained on.

The sharpest result is the arm with the math block on the input but an ordinary digit head on the output: it reaches 100% inside the training range and 0% outside it. Structure has to be on both ends. Full tables in E3.
Experiment E1  ·  experiments/e1_exactness.py

Is the algebra exact, with zero learned parameters?

Millions of random operand pairs are pushed through the codec and the decoded answer is compared against ground truth computed in ordinary Python integers. Nothing here is trained, so a single counterexample would sink the whole idea — the point of running millions of trials is that there is nowhere for one to hide.

Implementation

What the script actually does

  1. Build the codec. MathCodec.for_integers() takes primes (5, 7, 11, 13, 17, 19, 23), so M = 37,182,145 and the block is 35 reals. The constructor precomputes, per prime, a primitive root, the full discrete-log table, and the p legal five-slot patterns. All of it is a fixed table; there are no parameters to fit.
  2. Sample operands in bulk. A seeded np.random.default_rng(0) draws 200,000 pairs per check. Everything is vectorised — encode takes an array of integers and returns an array of blocks, so a check is three lines.
  3. Compare against exact integer arithmetic. Ground truth uses Python's arbitrary-precision integers (a.astype(object) * b) so the reference itself never overflows.
  4. Measure the bare bilinear step separately. add_raw is one elementwise complex product — no lookup, no branch. Its additive channels are compared directly against E(a+b)'s, which is where the 1.9 × 10⁻¹⁵ figure comes from. For mul_raw the claim is made only on channels where a discrete log exists, i.e. where neither operand vanishes mod p.
  5. Check the square, not just the number. The round-trip block compares op(E(a), E(b)) against E(a op b) slot by slot, and counts blocks where every slot agrees to 10⁻¹².
  6. Push past the integers. A second codec with primes above 100 stores rationals; reading back is lattice rational reconstruction. Denominators sharing a factor with M are rejected by the zero-flag certificate rather than answered wrongly.
experiments/e1_exactness.py — the core of one check 
a = rng.integers(0, M, size=n_trials)
b = rng.integers(0, M, size=n_trials)
got, conf = codec.decode(codec.add(codec.encode(a), codec.encode(b)))
check("random pairs, full range", got, (a + b) % M)

# the bare bilinear step, with the refresh removed
raw = codec.add_raw(codec.encode(a), codec.encode(b))
ref = codec.encode((a + b) % M)
sl  = np.concatenate([codec.idx_add_cos, codec.idx_add_sin])
err = float(np.abs(raw[:, sl] - ref[:, sl]).max())     # -> 1.9e-15

Division, and the block's own certificate

Division is exact when the divisor is coprime to M. When it is not, the honest thing is to say so. The block carries the answer locally: a divisor is invertible exactly when every zero flag is off, which needs no decoding at all. Experiment E2  ·  experiments/e2_noise.py

How wrong may the model be before the decode breaks?

E1 says the algebra is exact. That is not the question that decides whether the block is usable, because a network never emits the numbers you asked for. This was the objection raised in the session against similarity decoding: early in training, nothing is close to anything. So the quantity that matters is the noise budget — and it turns out to be a knob you can set.

Implementation

What the script actually does

  1. Draw 20,000 values from [0, payload), where payload is the redundancy-2 range (85,085) — the range that stays uniquely decodable after discarding two primes. Encode them all once.
  2. Sweep σ over 41 values from 0 to 0.5 and add iid Gaussian noise to every one of the 35 slots: clean + rng.normal(0, s, clean.shape). No slot is protected, and the noise is independent per slot rather than a rotation of the block.
  3. Decode three ways from the same noisy array, so the comparison is paired: phase-only reads one angle per prime and runs CRT; ML picks the nearest of the p legal five-slot patterns; ML+RRNS then reconstructs from every drop-one prime subset and keeps the candidate consistent with the most residues.
  4. Score exact recovery, not distance: the decoded integer either equals the original or it does not. The reported threshold is the largest σ still at ≥99%.
  5. Re-run the whole sweep at redundancy 0, 2 and 4 to show the trade explicitly. Spare primes buy either representable range or noise headroom, and this is the exchange rate.

for s in sigmas:

    row = {
        "sigma":      float(s),

        "ml":         float((codec.crt(ml_res)    == values).mean()),
        "ml_rrns":    float((codec.decode_robust(noisy, redundancy=2)[0] == values).mean()),

Experiment E3  ·  experiments/e3_transformer.py

Does a transformer actually benefit from the math block?

Five arms share one backbone — 2 layers, 4 heads, d_model 128 — so any difference comes from the embedding and the head, not from capacity. Each arm is scored twice: on held-out problems from the training range, and on operands strictly larger than anything seen in training. The whole point of putting structure in the embedding is that the second column should not collapse.

Implementation

What the script actually does

  1. Freeze every table first. The Tables class precomputes the Kronecker word block for every number token and the 35-dim math block for every number. Neither is ever trained — only the model's input projection is. A number is a single token, and its embedding is computed from its bytes, so a number never seen in training is still representable.
  2. Lay out four positions — a, op, b, = — each a feature vector of 64 word + 35 math + 1 is-number = 100 reals. Arm B is exactly arm C with the math slice left at zero; that one line is the entire difference.
  3. Vary the head, not the trunk. Three heads exist: regress the 35-dim block (MSE), one small softmax per prime (95 logits, cross-entropy), or six 10-way digit softmaxes. The digit baseline additionally swaps the input for a learned embedding table over the 14-symbol digit spelling.
  4. Train identically. AdamW, one-cycle LR to 1e-3, gradient clipping at 1.0, 6,000 steps of batch 512, seed fixed. Arms differ only where the list above says they differ.
  5. Decode the block output robustly. A regressed block is a noisy block, so prediction runs it through decode_robust(..., redundancy=2) — the same error-correcting decoder E2 measured. The block RMSE is recorded alongside, which is what lets the E2 budget and the E3 measurement be compared.
  6. Include a zero-parameter reference. The closed-form operator is run on the same OOD problems. It needs no model at all, and it is the ceiling every arm is being measured against.
experiments/e3_transformer.py — the feature layout, and the one-line difference between arms B and C 
def features(self, a, b, op, use_math):
    f = np.zeros((len(a), 4, self.feat_dim), dtype=np.float32)
    for pos, arr in ((0, a), (2, b)):
        f[:, pos, :self.d_word] = self.kron_num[arr]              # spelling
        if use_math:                                              # <-- arm B: False
            f[:, pos, self.d_word:self.d_word + self.codec.dim] = self.math_num[arr]
        f[:, pos, -1] = 1.0                                       # is-number flag
    f[:, 1, :self.d_word] = self.kron_sym[op]
    f[:, 3, :self.d_word] = self.kron_sym["="]
    return f

Experiment E4  ·  experiments/e4_mixed_lm.py

Can words and numbers coexist in one sentence?

E3 fed the model a bare expression. The assignment asks for something stronger: keep the existing 32 byte-slots doing their job for alphabets and words, and append the math dimensions. So the input here is a sentence, and the model has to do two different things at once — read the words to work out which operation is being asked for, and do the arithmetic on operands larger than any it saw in training.

Implementation

What the script actually does

  1. Twelve surface forms, three operations. Four templates each for add, subtract and multiply, deliberately varied in length and keyword position so the model cannot shortcut by counting tokens or looking at one slot. Subtraction swaps its operands when b > a, to keep answers non-negative.
  2. One frozen feature table covering [pad] + 27 words + every number token. Each row is 64 Kronecker word + 35 math + is_number + is_pad = 101 reals. Words get a word block and a zeroed math block; numbers get both.
  3. Sentences are left-padded to 11 tokens so the answer is always read off the last position, and the model never learns to key off sequence length.
  4. The two arms differ by one line. feats[:, math_slice] = 0.0 for the word-block-only arm. Identical sentences, identical word blocks, identical trunk (d_model 192, 3 layers), identical 8,000 training steps.
  5. The target is the answer's math block, trained with plain MSE; prediction decodes it with the redundancy-2 error-correcting decoder. Accuracy is scored per operation as well as overall, because the per-operation split is the actual claim: the word block picks the operation, the math block does the arithmetic, and they do not interfere.
experiments/e4_mixed_lm.py — building the frozen token table 
def build_feature_table(codec, n_max):
    """One frozen table: [pad] + [words] + [every number]. Nothing is trained."""
    kron  = KroneckerWordBlock(d_word=D_WORD, window=32, seed=0)
    dim   = D_WORD + codec.dim + 2               # word | math | is_number | is_pad
    table = np.zeros((NUM_BASE + n_max, dim), dtype=np.float32)
    table[PAD_ID, -1] = 1.0
    for w, i in WORD2ID.items():
        table[i, :D_WORD] = kron.encode_one(w)                    # words: spelling only
    nums = np.arange(n_max)
    table[NUM_BASE:, :D_WORD] = np.stack([kron.encode_one(str(i)) for i in nums])
    table[NUM_BASE:, D_WORD:D_WORD + codec.dim] = codec.encode(nums)   # numbers: both
    table[NUM_BASE:, -2] = 1.0
    return table

Experiment E5  ·  experiments/e5_linear_refresh.py

Can the last non-linear piece be made a fixed matrix?

The compact codec refreshes one channel from the other with a small fixed lookup. That is parameter-free, but it is not linear, and a reviewer is entitled to ask whether the whole construction can be done with nothing but an elementwise complex product and a fixed matrix. It can. The price is dimension, and this experiment measures both halves of that trade.

Implementation

What the script actually does

  1. Stop storing one harmonic; store the whole character basis. For each prime, keep all p additive characters A_k(r) = exp(2πi·k·r/p) and all p−1 multiplicative characters X_j(r) = exp(2πi·j·dlog(r)/(p−1)), plus the zero flag. That is 4p−1 reals per prime instead of 5.
  2. Notice both are the DFT of the same object. A is the DFT of the residue indicator δ_r over ℤ_p; X is the DFT of the same indicator over ℤ_{p−1} after relabelling by discrete log. Two unitary changes of basis on one underlying vector — so converting between them is a fixed matrix.
  3. Compose exactly as before. Addition is the Hadamard product on A; multiplication is the Hadamard product on X with the same bilinear zero-flag update. Only the refresh changed.
  4. Verify the claim three ways. That 20,000 additions and 20,000 multiplications still decode exactly; that the result deviates from E(a+b) by under 3.3 × 10⁻¹⁴; and — the actual point — that each refresh map satisfies f(αx + βy) = αf(x) + βf(y) on random vectors, to 5 × 10⁻¹⁵.
  5. Report the cost honestly. 373 dimensions instead of 35. The compact codec is what you would ship; this is what you would cite.
ringemb/linear_refresh.py — both refreshes, one matrix multiply per prime 
def refresh_from_add(self, vec):          # A -> (delta) -> (z, X)
    delta = A @ self.Finv[i].T
    X     = delta @ (self.G[i] @ self.Q[i]).T
    z     = delta[..., 0].real

def refresh_from_mul(self, vec):          # (z, X) -> (delta) -> A
    delta = X @ (self.Ginv[i].T @ self.Q[i])
    delta = delta + z[..., None] * np.eye(p)[0]
    A     = delta @ self.F[i].T
